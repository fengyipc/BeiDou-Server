# 技术架构

## 1. 整体架构设计

### 1.1 架构概览

BeiDou-Server 采用分层架构设计，从下到上依次为：数据层、数据访问层、业务逻辑层、网络层和表现层。

```
┌─────────────────────────────────────────────────────────┐
│                    表现层 (Presentation)                │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐ │
│  │   游戏客户端   │  │   Web 后台    │  │   API 接口   │ │
│  └──────────────┘  └──────────────┘  └──────────────┘ │
└────────────────────────┬──────────────────────────────┘
                         │
┌────────────────────────▼──────────────────────────────┐
│                     网络层 (Network)                   │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐ │
│  │  LoginServer │  │ ChannelServer │  │  Netty 框架  │ │
│  │   登录服务器   │  │   频道服务器   │  │  网络通信层  │ │
│  └──────────────┘  └──────────────┘  └──────────────┘ │
└────────────────────────┬──────────────────────────────┘
                         │
┌────────────────────────▼──────────────────────────────┐
│                   业务逻辑层 (Service)                 │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐  │
│  │ 角色服务  │ │ 地图服务  │ │ 物品服务  │ │ 任务服务  │  │
│  ├──────────┤ ├──────────┤ ├──────────┤ ├──────────┤  │
│  │ 公会服务  │ │ 商城服务  │ │ 聊天服务  │ │ 副本服务  │  │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘  │
└────────────────────────┬──────────────────────────────┘
                         │
┌────────────────────────▼──────────────────────────────┐
│                  数据访问层 (DAO/Mapper)               │
│  ┌─────────────────────────────────────────────────┐  │
│  │           MyBatis-Flex ORM 框架                   │  │
│  └─────────────────────────────────────────────────┘  │
└────────────────────────┬──────────────────────────────┘
                         │
┌────────────────────────▼──────────────────────────────┐
│                      数据层 (Data)                     │
│  ┌─────────────────────────────────────────────────┐  │
│  │              MySQL 8.0+ 数据库                   │  │
│  └─────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘
```

### 1.2 核心组件

#### Server 核心服务器
- 单例模式设计，全局唯一实例
- 管理所有世界、频道、公会、联盟
- 协调各个子系统工作
- 提供全局访问接口

#### Client 客户端会话
- 基于 Netty Channel 的会话管理
- 处理玩家登录、数据同步
- 管理玩家状态和连接
- 封包的接收和发送

#### Channel 频道服务器
- 独立的频道运行实例
- 管理频道内的玩家、地图、怪物
- 处理频道内的游戏逻辑
- 玩家数据持久化

## 2. 网络架构

### 2.1 网络通信模型

BeiDou-Server 采用 Netty 框架实现高性能网络通信。

#### 连接模型
```
客户端
  │
  ├─ LoginServer (8484端口)
  │   ├─ 登录认证
  │   ├─ 角色列表
  │   └─ 服务器选择
  │
  └─ ChannelServer (8600+端口)
      ├─ 角色登录
      ├─ 游戏逻辑处理
      └─ 数据同步
```

#### 封包处理流程
```
客户端发送封包
    │
    ▼
[Netty Decoder] - 封包解密和解码
    │
    ▼
[PacketProcessor] - 根据 Opcode 分发到对应 Handler
    │
    ▼
[Handler.handlePacket] - 处理游戏逻辑
    │
    ▼
[业务服务层] - 调用对应服务
    │
    ▼
[数据持久化] - 保存到数据库
    │
    ▼
[PacketCreator] - 创建响应封包
    │
    ▼
[Netty Encoder] - 封包加密和编码
    │
    ▼
发送给客户端
```

### 2.2 封包结构

```
┌────────┬────────┬──────────┬────────────┐
│ Header │ Opcode │  Length  │   Data     │
│ 2bytes │ 2bytes │  4bytes  │ N bytes    │
└────────┴────────┴──────────┴────────────┘
```

- **Header**: 封包头标识
- **Opcode**: 操作码，标识封包类型
- **Length**: 数据长度
- **Data**: 实际数据内容

### 2.3 网络安全

#### 加密机制
- 封包加密: AES 加密
- 登录认证: BCrypt 密码哈希
- 会话管理: Session ID 验证
- 防外挂: HWID/MAC 地址绑定

#### 反作弊机制
- IP 封禁系统
- HWID 封禁系统
- MAC 地址过滤
- 多开限制
- 异常行为检测

## 3. 数据库架构

### 3.1 数据库设计原则

- **规范化**: 遵循第三范式，减少数据冗余
- **索引优化**: 合理使用索引提升查询性能
- **分表策略**: 按功能模块分表
- **版本管理**: 使用 Flyway 进行版本控制

### 3.2 核心数据表

#### 账号系统
- `accounts`: 账号基本信息
- `ipbans`: IP 封禁记录
- `hwidbans`: HWID 封禁记录
- `macbans`: MAC 地址封禁

#### 角色系统
- `characters`: 角色基本信息
- `inventory`: 背包物品
- `equips`: 装备详情
- `skills`: 技能数据
- `keymap`: 快捷键设置

#### 游戏系统
- `buddylist`: 好友列表
- `parties`: 组队信息
- `guilds`: 公会信息
- `alliances`: 联盟信息
- `families`: 家族信息

#### 交易系统
- `mts`: 拍卖行
- `shops`: 玩家商店
- `shops_items`: 商店物品

#### 任务系统
- `queststatus`: 任务状态
- `monsterbook`: 怪物图鉴

### 3.3 数据库连接池配置

```yaml
mybatis-flex:
  datasource:
    mysql:
      type: com.alibaba.druid.pool.DruidDataSource
      driver-class-name: com.mysql.cj.jdbc.Driver
      url: jdbc:mysql://localhost:3306/beidou
      username: root
      password: root
      # 连接池配置
      initial-size: 5
      max-active: 100
      max-wait: 60000
      min-idle: 10
```

## 4. 业务架构

### 4.1 服务层设计

#### 服务分层
```
Controller (控制层)
    │
    ▼
Service (业务服务层)
    │
    ├─ AccountService - 账号服务
    ├─ CharacterService - 角色服务
    ├─ InventoryService - 背包服务
    ├─ QuestService - 任务服务
    ├─ ShopService - 商店服务
    ├─ GuildService - 公会服务
    └─ ... 其他服务
    │
    ▼
Mapper (数据访问层)
    │
    ▼
Database (数据库)
```

#### 事务管理
- 使用 Spring 事务管理
- 基于 `@Transactional` 注解
- 支持事务传播和隔离级别配置

### 4.2 缓存策略

#### 内存缓存
- **PlayerStorage**: 玩家数据缓存
- **Guild 缓存**: 公会数据缓存
- **Alliance 缓存**: 联盟数据缓存
- **BuffStorage**: 状态效果缓存

#### 缓存失效
- 玩家下线时清除缓存
- 数据更新时同步缓存
- 定时清理过期数据

- 与 Java 互操作性强

#### 脚本类型

## 6. 并发架构

### 6.1 线程模型

#### 虚拟线程
- 使用 Java 21 虚拟线程
- 轻量级线程，减少上下文切换开销
- 适用于 I/O 密集型操作

#### 线程池
- **ThreadManager**: 游戏线程管理
- **TimerManager**: 定时任务线程池
- **Netty EventLoop**: 网络事件处理线程

### 6.2 并发控制

#### 锁机制
- **ReadWriteLock**: 读写锁，保护共享数据
- **ReentrantLock**: 可重入锁，同步客户端操作
- **Semaphore**: 信号量，限制并发操作数

#### 并发集合
- **ConcurrentHashMap**: 并发安全的 Map
- **CopyOnWriteArrayList**: 读多写少的列表
- **BlockingQueue**: 阻塞队列，用于任务调度
