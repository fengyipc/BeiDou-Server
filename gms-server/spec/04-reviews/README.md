# 代码审查 Reviews

本目录存放代码审查记录。

## 目录结构

```
04-reviews/
├── README.md           # 本文件
└── [关联Tasks编号]/    # 按 Tasks 关联组织
    └── review-xxx.md  # 审查记录
```

## 审查编号规则

`REVIEW-YYYY-NNN`
- `YYYY`: 年份
- `NNN`: 序号

示例：`REVIEW-2026-001`

## 审查类型

| 类型 | 说明 | 流程要求 |
|------|------|----------|
| `feature` | 功能开发 | 完整流程 |
| `fix` | Bug 修复 | 可简化 |
| `refactor` | 重构 | 完整流程 |
| `hotfix` | 热修复 | 事后补全 |

## 审查结论

| 结论 | 说明 |
|------|------|
| `approved` | 通过，可合并 |
| `requested_changes` | 需要修改 |
| `rejected` | 拒绝，需重大修改 |

## 审查标记

| 标记 | 含义 | 要求 |
|------|------|------|
| `[must-fix]` | 必须修复 | 是合并前提 |
| `[should-fix]` | 应该修复 | 建议处理 |
| `[suggest]` | 建议改进 | 可选择性处理 |
| `[nit]` | 小问题 | 格式等 |
| `[question]` | 需要澄清 | 必须回复 |

## 审查清单

每次审查必须检查：

### 功能性
- [ ] 代码实现了需求规格中描述的功能
- [ ] 所有分支路径都被正确处理
- [ ] 错误处理逻辑完善

### 安全性
- [ ] 无 SQL 注入风险
- [ ] 权限检查正确
- [ ] 敏感信息不暴露

### 可读性
- [ ] 命名清晰表达意图
- [ ] 方法长度适中
- [ ] 注释解释"为什么"

### 性能
- [ ] 无明显性能问题
- [ ] 数据库查询已优化
- [ ] 资源使用后正确释放
